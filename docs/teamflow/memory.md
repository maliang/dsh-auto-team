# 产品记忆（跨需求约定，按主题替换同一行，不做变更日志）

## 技术栈
- dsh 插件 `dsh-auto-team`：TypeScript + 双构建（宿主 `lib/index.js` 为 ESM、client `lib/client.js` 为 CJS 且套 `__ModuleLoader__` 壳）；声明用 `dsh.bundle.patch` + `dsh.client`，字段集合照本机已装样本 `~/.dsh/profiles/desktop/node_modules/dsh-plugin-teamflow/package.json`。
- 多智能体编排复用宿主服务：`ctx.agentTeams`（`spawnTeammate`/`listMembers`/`tryMembership`）+ `ctx.tools.register` + `ctx.systemPrompt.section` + `ctx.slots.inject/register`；不重造成员与消息通道。
- per-role 模型/人设：官方 Team 请求不带 `agentOptions`，必须在串行 `agent/created` 事件上安装成员级路由，并用 `llm.resolveCallConfig()` 预校验（否则静默沿用队长模型）。
- UI 挂载点：输入框下方 = `conversation.composer.dock`（kind=list/session，渲染于 `[data-composer-dock]`）；`conversation.input.dock` 在输入卡上方，别混用。

## 安装与运行
- 本机 `dsh` 不在 PATH：装/卸走 `cd ~/.dsh/profiles/desktop && pnpm add file:<repo>` / `pnpm remove <pkg>`，并同步 `package.json` 的 `dsh.profile.bundles`；profile=desktop。
- 安装只能由主 agent 执行（流水线子代理权限固定在工作区内，写不了 profile）。
- 数据落点：运行状态 `~/.dsh/auto-team/runs/`、会话开关 `~/.dsh/auto-team/sessions.json`、角色 `~/.dsh/auto-team/roles/*.md`、公共记忆 `~/.dsh/auto-team/memory/public/`、项目记忆 `<workspace>/.auto-team/memory/`、门禁日志 `<workspace>/.auto-team/artifacts/`。

## 工程约定（脚手架已落地，详见 docs/teamflow/architecture/ARCHITECTURE.md）
- 分层：`src/shared` 纯类型 ← `src/host`（node）/ `src/client`（浏览器）；**host 与 client 零直接 import**，只走 `GET|POST /api/auto-team`。
- 宿主 API 只许出现在 `src/host/adapters.ts`；宿主形状变动只改这一个文件。
- 本地 import 一律带显式 `.ts` 扩展名（`node --test` 直接跑 TS 源的前提）；纯逻辑模块不许 import 宿主。
- `tsconfig` 的 `jsx` 必须是 classic `"react"`（client 的 `require` 由宿主提供，不保证解析 `react/jsx-runtime`）。
- client 产物必须保留 `typeof window !== "undefined" && window.__ModuleLoader__` 守卫，否则 node 侧 `await import('./lib/client.js')` 自检会失败。
- `cordis.patch.yml` 的 `name` 必须是包根名 `dsh-auto-team`（写子路径会让 clientModules 扫描跳过，症状：工具在、面板不出现）。
- 前端样式只用宿主 token；字号写 `font: var(--dsw-font-xs-13, …)`，**不许写 `font-size: var(...)`**（该 token 是 font 简写复合值，写 font-size 是无效声明且静默继承父级）。
- 前端读接口必须解构 `{data,error}` 包装（历史高频 bug 族：整包赋值 → 界面"点了没反应"）。
- 面板可视约束（r4 DESIGN 实测，后续别再试错）：成员行网格 `76px minmax(96px,1fr) 64px 44px` 的列宽冻结，**不要往状态列塞复合徽标**（「运行中·停滞」实测需 ≥110px，会撑破网格），新增的横向提示走跨全宽插槽 `grid-column: 1/-1`；11px 正文不得用琥珀 `--dsw-alias-state-warn-primary`（在 `bg-layer-1` 上对比度约 3.2:1，不达标），琥珀只用于非文本位置（竖条/图标/描边/微底），文字用 `--dsw-alias-label-secondary`；账本正文折叠用 `max-height`，不要 `-webkit-line-clamp`（`white-space: pre-wrap` 的多行正文会被 `-webkit-box` 算坏换行）。
- 成员名是身份契约（20261031-r2 已落地）：`<slug(roleId)>-<slug(taskId)>-<6 位身份哈希>`，哈希输入是**原始** `roleId\0taskId` 的 FNV-1a 32 → base36 末 6（`dispatch.ts` `shortIdentityHash`），截断只裁可读段、**永不裁哈希**（`NAME_BUDGET = HOST_MEMBER_NAME_MAX 48 - 6 - 1`，48 只在 `config.ts` 定义一次）。`dispatchReady` 循环前先算一次全计划占用（`allocateMemberNames`，循环外一次性求值的纯函数、不读 RunState，含未退役 binding 名与宿主现存成员名；`listMembers` 抛错时宿主名按**空**处理、不做保守预留——保守预留会让重试拿到新序号、破坏「名字恒定」，真撞名由宿主 spawn 失败以 `errors` 可观测），撞名任务按**确定性序号**消歧后继续派发：`base`、`base-2`、`base-3`… 取首个未被占用的名字，只压缩可读段以守住 48（`-2` 不得拼在尾部硬撑超过上限），身份哈希段逐字保留；分配必须一次性按稳定计划顺序完成（不能边派边算，否则「谁先被调度」决定名字），同一任务已有未退役 binding 时**沿用其名不改号**（否则恢复时名字递增、成员翻倍）。每次消歧产出**一条** `ActResult.notices`（含 taskId/原候选名/最终名），不写 `errors`；`MEMBER_NAME_COLLISION` 只在序号空间耗尽时作为可观测兜底。新增同类能力时照此办理：单任务视角的「符合宿主字符集」测试看不到塌缩，必须断言「同角色多任务两两唯一」。
- 直通投递（20261101-r4 第一期）：依赖任务 `done` 且门禁 `exitCode===0` 时，`applyReceipt` 的 done 分支直接把上游产物与证据投给每个 `dependsOn` 下游 —— 账本记 `from:'peer'`（不经队长、**不新增一条 captain 转述消息**），下游成员已存在则 `bridge.act('receipt')` 后按 `toMemberId` 实发，未创建则靠 `SpawnInput.handoffs`（`PromptInput = Omit<SpawnInput,'prompt'>` 自动继承）在 `buildMemberPrompt` 注入首条提示词。body 与幂等键只允许在 `src/host/team/handoff.ts` 一处拼装：`handoffBody()` 五段（上游 id+title / 命令 / 退出码 / 证据**末** `HANDOFF_TAIL_CHARS=800` 字 / 产物路径或「无落盘产物」），`handoffId(a,b) = handoff:<a>-><b>`。**peer 消息必须直接构造 `MessageRecord`，绝不能走 `makeMessage`**（`team/messages.ts` 无条件写 `messageId:'msg-<at>-<seq>'`，会盖掉幂等键；症状是「单跑绿、重放才红」，是最难 debug 的一类）。
- 停滞检测（20261101-r4）：阈值 `STALL_MS = 90_000` 只在 `src/host/config.ts` 定义一次；判定实现在纯逻辑 `src/host/team/stall.ts` 的 `stallOf(progressAt, baseline, now, stallMs)`（阈值只作参数、不自读常量，便于单测注入），**两条入口共用同一份实现** —— 告警出口唯一在 `watcher.stallAlertsOf(state, now, stallMs)`（tick 顺序 reconcile → stall → 有变更才 save，复用既有 1500ms；全仓 `setInterval(` 仍只 1 处），展示出口在 `bridge.membersOf` 调同一个 `stallOf`。一个 episode 恰好一条 `kind:'tool'` 活动事件，幂等靠落盘 `progress[memberId].alertedAt`，恢复即 `clearAlerted`；停滞**绝不改 `task.status`**。快照只下发给客户端 `stalled` / `stalledForMs` / `stalledSecondsText` 三字段（客户端零阈值、零秒数格式化，避免宿主与客户端两套格式分叉）。秒数分档：`<600s → 「N 秒」，≥600s → 「M 分 S 秒」`。
- 日志脚本是回归契约：一次性检查器一律放 `logs/teamflow/<runId>/scripts/`（项目内暂存，run 结束由 host 归档到 `$DSH_HOME`，**不入库**），逐轮沿用、只许原地扩展，不许另起 `-run2`/`-v2` 兄弟文件。r4 起多两个入口：`qa-peer-probe.mjs`（直通投递 P1~P7）与 `qa-stall-probe.mjs`（停滞 S1~S4 + `--mutate=no-progress` 变异红）；`qa-reverify-probe.mjs`（9/9）与 `qa-collision-probe.mjs`（12/12）不降项。探针纪律：依赖模块缺失时打印 `MISSING [module:x]` 并 **exit 1**，绝不静默算通过（否则「实现没落盘」会被记成「检查通过」，这是最容易出的假绿）。
- 验证命令：`pnpm typecheck && pnpm test && pnpm build`，外加两条 `node --input-type=module -e "await import('./lib/…')"` 与 `npm pack --dry-run`（须含 `lib/index.js`、`lib/client.js`、`cordis.patch.yml`）。实测基线快照（每次收口重测，别转抄）：2026-10-31 r3 = typecheck exit 0、**164 tests 全绿**（r2 基线 155，r3 起 164）、产物 `lib/index.js` 136.3 kB + `lib/client.js` 92.2 kB、单测跑 TS 源约 3.0s；2026-11-01 r4（验收终态，直通投递 + 停滞检测均落盘）= typecheck exit 0、**216 tests 全绿**（3.06s）、`lib/index.js` 160.48 kB + `lib/client.js` 99476 B，且 `find src -name '*.ts' -newer lib/index.js | wc -l` = 0 是「双产物与源码同步」的判据。**注意**：AC-8 往 `peerDependencies` 补了 7 个未发布的 `@deepseek-ai/*` 后，本仓 `pnpm install` 会因 `pnpm-lock.yaml` 的 `settings.autoInstallPeers: true` 报 `ERR_PNPM_OUTDATED_LOCKFILE` / `ERR_PNPM_FETCH_404`；可行解是 `.npmrc` 写 `auto-install-peers=false`（peer 由宿主 profile 提供）后 `pnpm install --lockfile-only` 重生成，再用五项门禁复验。

## 工具与流程坑（踩过就去掉一次重试成本）
- `cordis_inspect_query`：`input` 必须是对象（`{}` 也行）。host 侧 provider：`Service/listService`、`Event/listEvents`、`Config/listConfigs`、`Tool/listTools`；client 侧：`Service/listService`、`Event/listEvents`、`Builtin/listBuiltins`、`Slots/listSubTree`、`Theme/listTokens`。`Service/listService` 返回的 `signature` 是**方法签名目录**（不含 type 字段），能确认方法名与参数个数，不能确认请求对象字段名。
- 实例化的关键签名（`input: {}` 实调结果）：`agentTeams.spawnTeammate(caller: Agent, request: SpawnTeammateRequest): Promise<SpawnTeammateResult>`、`agentTeams.sendMessage(caller, request: SendTeamMessageRequest): Promise<SendTeamMessageResult>`、`agentTeams.{membership,listMembers,createTask,getTask,listTasks,updateTask,waitForChange,interrupt,tryMembership}`；`tools.{register(definition): ()=>void, guard, get, schemas, execute}`；`systemPrompt.{section(section): ()=>void, context, tools, variable, assemble}`；`webServer.{register(route: WebRoute): ()=>void, registerUpgrade, tapIndex, renderIndex}`；`llm.resolveCallConfig(config: LlmCallConfig, signal?): Promise<LlmCallConfig>`；`subagents.{startActivation,sendMessage,interrupt,listChildren,listDescendants,resolveMaxDepth}`。
- `toolflow` 阶段熔断教训：scaffold 阶段单阶段新增 token 上限 350k，超了直接熔断失败。**续跑时不要重写已落盘文件** —— 先读 `docs/teamflow/architecture/ARCHITECTURE.md`（含 §8.1 已验证清单 / §8.2 未验证清单），只补齐缺口与核实 `[待核]` 项，避免重复劳动再次烧穿预算。
- **`cordis_inspect_query` 查单个对象用 `input: {"event": "<name>"}` / `{"service": "<name>"}`**（列全部用 `{}`）。2026-11-01 实测：传字符串或非对象会被宿主拒成 `rejected input: "input" must be an object`，两轮阶段把它误判成 env-unavailable 并反复重试，各烧掉 ~300k 新增 token 触到预算熔断。**见到这条错误先改调用姿势，不要换方案、不要重试同一形状。**
- **观测成员工具调用（停滞检测数据源）订阅 `tools/result`（emit），不要订阅 `tools/execute`（waterfall）**：前者签名 `(exec: Readonly<ToolExecution>, result)`、监听器异常被隔离；后者必须 `next()`，漏调会吞掉工具执行。宿主文档明确「`tools/result` 的 scope 过滤 keyed by `exec.agent`」——在 `agent.ctx` 上注册的监听器**只收到该 agent 的调用**，`adapters.ts` 的 `agentContextOf(agent)` 可直接复用（与 `installMemberRoute` 同一机制），不需要 id 过滤、不需要全局监听。
- `exec` 形状：`callId` / `rootCallId?` / `name` / `schema?` / `arguments` / `agent?: Agent{id: SessionId}` / `parent?: ToolExecutionToken` / `signal`；嵌套子调用 `parent` 非空。
- 验收判据要「同时覆盖合法性与唯一性」：本轮的 R2-1 正是因为两轮 QA 都只断言「单个成员名符合宿主字符集」，把两个不同 id 放在一起才暴露塌缩——凡「身份/命名」类判据，必须构造**成对样本**做可分辨断言。
